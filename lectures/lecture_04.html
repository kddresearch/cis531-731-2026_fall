Lecture 04: Lab 1 – PySpark 4 Bring-up & The "Obtain" Stage

Initializing SparkSessions, StructType Schemas, and Environment Bring-Up

Session Overview

Welcome to Lab 1. Today, we bridge theoretical distributed computing concepts into practical execution by bringing up our PySpark 4 environments and executing the initial Obtain stage of the OSEMN pipeline.

Students will verify their containerized toolchains using verify_env.py, enforce strict schemas via StructType, handle malformed records, and lock in their team project tracks and multidimensional matrix allocations. Refer to the Environment Runbook for full setup specifications.

🐳 Environment Verification & Manifest

Ensuring strict version compatibility and determinism across host platforms.

  • Pinned Runtime: Python 3.10 slim, PySpark 3.5.1, Torch 2.2.1, FAISS-CPU 1.8.0.
  • SHA-256 Verification:
    6f0648c69f69b1faeb96cfecaa7e2a90
    4ed9210c8c07e0b5dd13d2f9df25ff75
  • Execution Script: Running verify_env.py inside the DevContainer. Consult the Environment Runbook page for step-by-step guidance.

📊 Schema Enforcement & Ingestion

Applying fail-fast mechanics during the OSEMN Obtain phase.

  • StructType Schemas: Explicitly defining data types to prevent silent failures.
  • Malformed Handling: Managing corrupt records via permissive vs. fail-fast modes.
  • Track Workflows: Supporting both VDB batch text and ASR streaming ingestion.

⚠️ Cross-Platform Environment Notice

Windows 11 users must verify their WSL 2 integration and Docker Desktop settings. MacOS (Intel/Apple Silicon) and Linux users should follow the parallel container socket and volume mount configuration guides detailed in the Environment Runbook to ensure proper root permissions and architecture compatibility.
