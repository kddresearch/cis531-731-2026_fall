Lecture 03: RDD Transformations & Actions Lab

Moving from Local Scripts to Distributed Architecture with PySpark 4

Session Overview

Welcome to Week 2. Today, we bridge the gap between writing Python scripts on your laptop and engineering data pipelines that run on clusters. We cover core data exploration concepts while executing them on the bleeding edge: PySpark 4.

By the end of this lecture, you will understand how Spark manages distributed memory via lazy evaluation and the Directed Acyclic Graph (DAG), and you will formally lock in your foundational architecture track for the term project.

⚙️ PySpark 4 Architecture & Execution

Moving beyond single-node compute limits to horizontal cluster scaling.

  • Driver & Executors: Master/worker node command and execution division.
  • Lazy Evaluation: Deferring compute pipelines until actions are invoked via DAGs.
  • DataFrame API: Catalyst Optimizer-backed operations replacing legacy RDDs.

🎯 Term Project Track Mandates

Committing to parallel operational pipelines for the semester.

  • Track 1 (ASR): Live radio stream capture and real-time transcription.
  • Track 2 (VDB): Literary corpus acquisition and semantic vector embeddings.
  • Immutability: Locking pipeline scope to maintain DAG structural integrity.

⚠️ Architectural Warning: Track Selection Lock

Once selected in Module 01/03, your project track cannot be switched. Ensure your development environment is fully synchronized with Docker and Beocat access prior to pipeline execution.
