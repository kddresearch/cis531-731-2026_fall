Term Project Guidelines

Design, Implementation, and Evaluation of an End-to-End OSEMN Data Science System

🎯 Architecture & Grading Structure

The Term Project is the capstone of CIS 531 / 731. It is evaluated via a dual-grading structure worth a total of 390 points across the semester:

  • Process Milestones (90 pts): You earn assignment points for completing the three mandatory project milestones on time: PS 4 (Proposal — 30 pts), PS 8 (Interim Report — 30 pts, due Sat 07 Nov 2026), and HW 12 (Final Submission Milestone — 30 pts, due Mon 14 Dec 2026).
  • Substance Evaluation (300 pts / 200-pt HW 12 Rubric Scale): Your final deliverables (the technical report, the digest-pinned MLflow codebase/pipeline, and the oral presentation/dashboard defense) are evaluated holistically against the Term Project Grading Rubric.

The Canonical 3x5x5 Data Cube Taxonomy: Every project is anchored across three orthogonal dimensions: (1) Analytical Category (Prescriptive, Descriptive, Predictive), (2) Media/Topic Row (Time-Series, Spatial, Text, Multimedia, Structured/Relational), and (3) OSEMN Execution Stages (Obtain, Scrub, Explore, Model, iNterpret), operating on either the ASR Track or the VDB Track locked at PS 4.

🧭 Click to Expand: The 3x5x5 Data Cube Matrix & Tier 1 / Tier 2 / Tier 3 Sourcing Rules

Dimension 1 × 2 × 3: The 3x5x5 Selection Matrix

Each team selects 1 Analytical Category table (Prescriptive, Descriptive, or Predictive) and 1 Media/Topic row, with each student claiming 1–2 OSEMN stages (unclaimed stages are automated/mocked via versioned Bronze → Silver → Gold Delta/Parquet/FAISS handoffs):

  • Table A — Prescriptive Analytics (RecSys / IR / RAG Automation): (1) Time-Series: Log Ingestion → Predictive Maintenance → Alert Dashboard; (2) Spatial: GPS Stream → Logistics Routing; (3) Text: API Scraping → Text Chunking → Topic Modeling → RAG Q&A System → Source Auditing; (4) Multimedia: ASR Capture → Content RecSys; (5) Structured: DB Polling → Knowledge Graph.
  • Table B — Descriptive Analytics (InfoVis / Storytelling / Drift): (1) Time-Series: Sensor Polling → Clustering → Drift Dashboard; (2) Spatial: GeoJSON Pull → Spatial Regression → Interactive Map; (3) Text: Archive Sync → Stopword/Regex → Word Embeds → Sentiment/Trope → Narrative Vis; (4) Multimedia: Video/Audio Stream → Feature Cluster → Media Timeline; (5) Structured: API Webhooks → Association Rules → Summary Dashboard.
  • Table C — Predictive Analytics (Classification / Forecasting): (1) Time-Series: Fin/Market/Weather API → ARIMA/LSTM → Forecast Curves; (2) Spatial: Remote Sensing → CNN Classifier; (3) Text: Social/Corpus Stream → Few-Shot LLM → ROC/AUC & Macro-F1; (4) Multimedia: Audio Stream → Acoustic/ASR Model → WER Metrics; (5) Structured: Transaction Logs → XGBoost/KYC → Precision/Recall.

🟢 Tier 1 (Golden Path — Required Default for CIS 531 Teams) vs. 🟡 Tier 2 (Real-World APIs — Expected for CIS 731 Teams)

  • Tier 1 (Golden Path): Databricks native samples (samples.wanderbricks, samples.tpcds_sf1), Hugging Face wikimedia/wikipedia or librispeech_asr, instructor-whitelisted ASR streams, Open-Meteo/NOAA weather endpoints, USGS Earthquake GeoJSON feeds. Note: Standard Yelp and SEC-filing grinds are prohibited.
  • Tier 2 (Real-World APIs & Benchmarks): Authenticated/parameterized REST APIs with raw JSON Bronze archival, Kaggle IEEE-CIS Fraud Detection, or custom multi-source corpora with documented licenses.
  • Tier 3 (Tarpits — Require Explicit Instructor Approval & Fallback): Raw Sentinel-2/STAC rasters, raw MFCC audio extraction on generic Spark workers, brittle HTML web scrapers, or unbounded live social-media collection.

👥 Teaming, Enrollment Track & Annotation Protocols

1. CIS 531 vs. CIS 731 Track & Schema Rules

  • CIS 531 Teams (Undergraduate Only): Must use a verified Tier 1 Golden Path source and adopt the instructor-provided ontology and chunk schema unmodified.
  • CIS 731 Teams (Graduate Only): Expected to use a Tier 2 Real-World API/Benchmark source and derive a custom ontology and JSON Schema (Draft 2020-12) (class hierarchy, relation types, cardinalities, change log, and competency questions), plus fit a learned 1-D PyTorch convolutional kernel in MP 9.
  • Mixed 531/731 Teams: Permitted to use Tier 2 sources, provided all schema/ontology inference tasks in Obtain, Scrub, and Explore are explicitly claimed and executed by the CIS 731 members.

2. Individual vs. Team Milestones & Annotation Bounds

  • Individual Homework Gates (MP 5, PS 6, MP 7, MP 9, MP 10, PS 11): Submitted individually via Git tags (`mp5-submission`, `ps6-submission`, `mp7-submission`, `mp9-submission`, `mp10-submission`, `ps11-submission`). In MP 9, each student labels at most 50 gold objects or 2 hours (enforced by a hard CI row-count gate; >50 rows returns a 0) with a 20-object partner overlap (overlap_ids.txt) for Cohen's $\kappa$ IAA.
  • Pooled Team Milestones (PS 8 Interim Report & HW 12 Final Deliverables): Submitted by the registered term-project team (or solo). In HW 12, teammates pool their adjudicated gold files to satisfy the 50–200 labeled-example range gate with 2-way/3-way IAA and adjudication rules (solo projects keep labeled validation data at $\le 1\%$).

Phase 1: Project Proposal (PS 4 — Completed)

The PS 4 Proposal milestone locked your immutable data track (ASRASR or VDB), 3x5x5 taxonomy coordinate, and initial source-to-Bronze plan. Any scope adjustments must be documented in Section 2 (Scope Delta) of your PS 8 Interim Report.

Phase 2: Interim Report (PS 8 — Due Sat 07 Nov 2026)

PS 8 (30 Points) is the second mandatory milestone. You must submit a single PDF (≤10 pages) with figure sources in interim/ under Git tag ps8-submission containing seven required sections:

  1. Team & Taxonomy Metadata (2 pts): Roster, Category, Media Type, claimed OSEMN stages, and the mandatory GenAI Integrity Attestation.
  2. Scope Delta & Proposal Responses (4 pts): Updated problem statement, justified scope changes since PS 4, and point-by-point responses to instructor PS 4 feedback.
  3. Data Provenance & Exploratory Baselines (10 pts): Provenance table (source, whitelist ID / license_class, size, ingest method), ≥3 Wilke-compliant exploratory figures (including a UMAP sensitivity sweep over n_neighbors and min_dist with fixed random_state and a cohort/drift plot with uncertainty), and advisory baseline metrics from MP 7.
  4. Architecture, Requirements, & Pillar Alignment (5 pts): End-to-end pipeline diagram, component-version table keyed to the course manifest, and enforced deal contract excerpts.
  5. Risk Register & Revised Annotation Plan (5 pts): At least 5 quantified risks (likelihood, impact, trigger, mitigation, including CPU/quota fallback) and your 50–200 annotation & IAA plan aligned with MP 9 and HW 12.
  6. GitHub Repository Link (2 pts): Active commit history under tag ps8-submission.
  7. GenAI Audit Log & Certificate (2 pts): Complete GenAI.pdf log under the "Grammarly on Steroids" policy.

Phase 3: Gold-Standard Construction, RAG & Statistical Evaluation (MP 7, MP 9, MP 10)

⚠️ Critical Path Timeline (Nov 3 → Nov 16 → Nov 25)

Your Phase 3 machine problems build the exact codebase and evaluation harness required for HW 12: MP 7 (due Tue 03 Nov) locks your Classifier interface and fixed-demo baseline; MP 9 (due Mon 16 Nov) builds your adjudicated gold set, 1,000-chunk silver pool, top-k RAG classifier, and cohort convolution analysis; and MP 10 (due Wed 25 Nov) builds your evaluate(model, X, y) harness, permutation importance, ECE calibration, and Benjamini–Hochberg paired statistical tests.

Phase 4: Ethics, Storytelling, Dashboards (PS 11) & Final Presentations

In PS 11 (due Fri 04 Dec 2026, before Dead Week), you will audit your pipeline for provenance, PII/privacy, ecological fallacy, and prompt-injection/hallucination risks, design a 5-view Wilke storyboard, and implement a restart-and-run-all dashboard prototype with a limitations panel (never reproduce copyrighted lyrics beyond instructor excerpts).

Standard Reflection Questions (Required in Final Presentation Slides)

In your presentation slides, EACH team member must individually answer the following three questions:

  1. What aspect of data science/machine learning did you find most technically challenging in completing this term project?
  2. What aspect of data science/machine learning do you think you learned the most about over the course of the project?
  3. What is your top priority for future work, if you were to continue this project as a research project or in independent study?

📅 Presentation & Dead Week Protocols

  • Dead Week Presentations (Optional Extra Credit): Run during Dead Week (Mon 07 – Fri 11 Dec 2026) after Lecture 40; they do not substitute for any part of the written/code HW 12 deliverable.
  • Finals Week (Mon 14 Dec 2026): HW 12 is due on Mon 14 Dec 2026 (the first day of Finals Week). No live presentations will be scheduled during Finals Week without prior written OSSA accommodation approval before the end of Week 16.

Phase 5: Final Report & Reproducible MLOps Package (HW 12 — Due Mon 14 Dec 2026)

Your unified final deliverables are submitted under Git tag hw12-final and shared with @banazir on GitHub:

  • The Final Technical Report (REPORT.pdf, ≤12 pages): Covers (1) Problem, Data, and Provenance (no Yelp/SEC data), (2) Methods, Architecture, deal Contracts, and Manifest Versions, (3) Evaluation on the 50–200 Gold Standard (IAA with CIs or $\le 1\%$ solo validation fraction, 95% CIs, ablations, BH-controlled significance tests, cohort-stratified results, error analysis), (4) Ethics, Limitations, and Implemented Mitigations from PS 11, (5) Reproducibility, MLOps, and Serving, and (6) GenAI.pdf Audit.
  • The Reproducible MLOps Package (hw12-final): Digest-pinned Dockerfile/DevContainer, lockfile, Makefile where make verify executes lockfile/digest checks, contract tests, the 50–200 gold-standard range gate, and headline-metric reproduction on the CPU baseline; MLflow run lineage and registered model entry; working serving path (checkpointed Structured Streaming job with restart for ASR; CLI/HTTP service with smoke test for VDB); and a PSI/KS drift-monitoring runbook.
